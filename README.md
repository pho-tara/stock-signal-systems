# 日本株テクニカルシグナル通知システム

日本株のウォッチリストを毎日自動でチェックし、テクニカル指標（ゴールデンクロス/デッドクロス・RSI・MACD）に基づく売買シグナルをLINEに通知し、あわせて現状をまとめたダッシュボードをWebページとして公開する仕組みです。GitHub Actionsで無料・無人稼働します。

**投資助言ではありません。** 一般的なテクニカル指標を機械的に組み合わせただけの参考情報であり、将来の値動きを保証するものではありません。投資判断は必ずご自身の責任で行ってください。

## セットアップ手順

### 1. GitHubアカウントを作成

https://github.com/signup にアクセスし、メールアドレスで無料アカウントを作成します。

### 2. リポジトリを作成

1. 右上の「+」→「New repository」
2. Repository name: 例 `stock-signal-system`
3. 「Public」または「Private」どちらでも可（Privateの場合もこの用途なら無料枠で十分です）
4. 「Create repository」

### 3. ファイルをアップロード

作成したリポジトリのページで「uploading an existing file」（またはリポジトリ内の「Add file」→「Upload files」）を選び、このフォルダの中身をすべてドラッグ&ドロップしてアップロードします。フォルダ構造（`.github/workflows/` 以下も含む）を保ったままアップロードしてください。うまくいかない場合は、GitHub Desktopアプリを使う方法もあります。

### 4. LINE公式アカウント・Messaging APIの準備

LINE Notifyは2025年3月末で終了しているため、後継のLINE Messaging APIを使います。

1. https://www.linebiz.com/jp/entry/ からLINE公式アカウントを作成（無料）
2. [LINE Developersコンソール](https://developers.line.biz/console/) にログインし、作成した公式アカウントに対応するプロバイダー・チャネル（Messaging API）を開く
3. 「Messaging API設定」タブで「チャネルアクセストークン（長期）」を発行し、値をコピーしておく
4. スマホのLINEアプリで、作成した公式アカウントを友だち追加しておく（QRコードはLINE Developersコンソールまたは公式アカウントマネージャーで確認できます）

※ 通知は「broadcast」（友だち全員に配信）方式にしているため、自分だけが友だち登録していれば実質的に自分専用の通知になります。他の人にも読まれたくない場合、他の人を友だち追加しないよう注意してください。

### 5. GitHubにLINEのトークンを登録

1. リポジトリの「Settings」→「Secrets and variables」→「Actions」
2. 「New repository secret」
3. Name: `LINE_CHANNEL_ACCESS_TOKEN`
4. Secret: 手順4でコピーしたトークンを貼り付けて保存

### 6. GitHub Pagesを有効化（ダッシュボード公開用）

1. リポジトリの「Settings」→「Pages」
2. 「Source」を「Deploy from a branch」、Branch を `main` / フォルダを `/docs` に設定して保存
3. 数分後に `https://(あなたのユーザー名).github.io/(リポジトリ名)/` でダッシュボードが見られるようになります（初回の自動実行後に反映されます）

### 7. 動作確認

1. リポジトリの「Actions」タブを開く
2. 左側の「日本株テクニカルシグナルチェック」を選択
3. 右側の「Run workflow」ボタンで手動実行
4. 数十秒〜1分程度で完了し、シグナルがあればLINEに通知が届き、`docs/index.html` が更新されます

以降は `.github/workflows/stock-check.yml` に設定したスケジュール（平日 朝8:00・後場終了後15:40、日本時間）で自動的に実行されます。

## 監視銘柄のカスタマイズ

`watchlist.py` を直接編集して銘柄コードと名称を追加・削除することもできます。証券コードの後ろに `.T` を付けた形式です（例: トヨタ自動車なら `7203.T`）。コードを編集したくない場合は、下記のIssueフォーム（④監視銘柄を追加／⑤監視銘柄を削除）からも登録・削除できます。

## 監視銘柄・保有銘柄の登録／買い時ランキングの設定（ダッシュボードから操作可能）

コードを直接編集しなくても登録・変更ができます。一番簡単なのは、ダッシュボードページ（`https://(あなたのユーザー名).github.io/(リポジトリ名)/`）の一番下にある「銘柄・設定の登録」から行う方法です。

1. ダッシュボードページを開き、「銘柄・設定の登録」セクションで該当する項目（証券コード・銘柄名・価格上限など）を入力
2. 「GitHubで登録する」ボタンを押すと、入力内容が自動で反映された状態でGitHubの登録画面（Issue作成画面）が新しいタブで開く
3. 内容を確認して「Submit new issue」を押す
4. 数十秒後に自動でファイルが更新され、Issueにコメントが付いて自動的にクローズされる（`.github/workflows/handle-registration.yml` が処理）

※ ダッシュボード自体は静的なページなので、その場で直接ファイルを書き換えることはできません。上記のボタンは「入力の手間を省いてGitHubの登録画面を開く」ためのものです。実際の反映にはGitHub側での「Submit new issue」のひと押しが必要です。

もちろん、GitHubの「Issues」タブ →「New issue」から直接テンプレートを選んで入力する方法でも同じことができます。

1. リポジトリの「Issues」タブ →「New issue」
2. 用意されているテンプレートから選択
   - **① 保有銘柄を追加**: 証券コードと銘柄名を入力すると、`holdings.py` に自動追加されます
   - **② 保有銘柄を削除**: 証券コードを入力すると、`holdings.py` から自動削除されます
   - **③ 買い時ランキングの価格上限を変更**: 金額を入力すると、`analyze.py` の`RANKING_PRICE_CEILING`が自動更新されます
   - **④ 監視銘柄を追加**: 証券コードと銘柄名を入力すると、`watchlist.py` に自動追加されます（保有はしていないが気になっている銘柄向け）
   - **⑤ 監視銘柄を削除**: 証券コードを入力すると、`watchlist.py` から自動削除されます
3. 「Submit new issue」を押すと、数十秒後に自動でファイルが更新され、Issueにコメントが付いて自動的にクローズされます（`.github/workflows/handle-registration.yml` が処理しています）

保有銘柄として登録された銘柄は、ウォッチリストとは別に「保有銘柄」セクションとしてダッシュボードに表示され、シグナル（買い/売り）が出るとLINE通知にも `[保有]` として含まれます（LINE通知を設定している場合）。監視銘柄（ウォッチリスト）は「特に気になっている銘柄」を手動で登録しておく用途で、日経225全体を対象にする「買い時ランキング」とは別枠として使えます。

もちろん、`holdings.py` / `watchlist.py` / `analyze.py` を直接編集する方法でも問題ありません。

### ラベルの事前作成が必要です（初回のみ）

Issueフォームのテンプレートに設定した「ラベル」は、リポジトリに存在しないと自動では付与されません。初めてこの機能を使う前に、リポジトリの「Issues」タブ →「Labels」→「New label」から、以下の5つのラベルを作成しておいてください（名前だけ設定すればOKです）。

- `add-holding`
- `remove-holding`
- `set-price-ceiling`
- `add-watchlist`
- `remove-watchlist`

ラベルが存在しない状態でIssueを作成すると、フォームは送信できても自動処理が実行されません（その場合はIssueを手動でクローズし、ラベル作成後に再度Issueを作成してください）。

## 買い時ランキングについて

日経225の構成銘柄（`nikkei225.py`）の中から、株価が指定した上限（デフォルト1500円）以下の銘柄を対象に、シグナル判定ロジックによる「買いの根拠の強さ」でランキングを作成し、ダッシュボードに上位20件を表示します。日経225の構成銘柄は入れ替えがあるため、`nikkei225.py` は定期的な見直しが必要です。

## ニュースのポジティブ/ネガティブ判定について

ダッシュボードの各銘柄に「ニュース」列があり、Googleニュース（無料・APIキー不要）でその銘柄名を検索し、直近の見出しに含まれるキーワードを数えて「ポジティブ」「ネガティブ」「中立」を機械的に判定して表示します。

- 好材料キーワード（例: 上方修正・最高益・増配など）と悪材料キーワード（例: 下方修正・赤字・リコールなど）を `news_sentiment.py` の `POSITIVE_KEYWORDS` / `NEGATIVE_KEYWORDS` に定義しています。追加・変更したい場合はここを編集してください。
- 判定は見出し1件につき1票の多数決です（好材料キーワードを含む見出しが多ければポジティブ、悪材料キーワードを含む見出しが多ければネガティブ）。1つの見出しに複数のキーワードが含まれていても1票としてしか数えません（例:「増収増益」は「増収」「増益」の両方に部分一致しますが、見出しとしては1票扱いです）。好材料・悪材料の両方のキーワードを含む見出しはどちらの票にも数えません。
- 文脈や皮肉、否定表現などは考慮できません（例:「赤字転落を回避」のような文でも「赤字」という単語だけを拾ってしまう場合があります）。
- **この判定結果は表示用の参考情報であり、テクニカルシグナル（`signals.py`）の判定やスコアには一切影響しません。**
- 対象は、ダッシュボードに実際に表示される銘柄（ウォッチリスト・保有銘柄・買い時ランキングの上位20件）のみです。日経225の225銘柄すべてに対してニュースを取得しているわけではありません（無料のGoogleニュース検索へのリクエスト数を抑えるためです）。同じ銘柄が複数のリストに重複して登場する場合も、ニュース取得は1回だけです。
- 費用は完全に無料です。

### （任意・追加費用あり）AI(Claude API)によるニュース判定を組み合わせる

無料のキーワード判定に加えて、Claude API(Haiku)にニュース見出し全体を読ませて判定させる、より精度の高いオプションも用意しています。ただし追加費用が発生するため、デフォルトでは無効になっています。

- **費用の目安**: 対象は表示される銘柄のみ（約40〜50銘柄）なので、**平日朝1回だけ**AI判定を使う設定で月額$0.5前後（数十円程度）です。頻度を増やすほど費用も増えます。
- **仕組み**: `.github/workflows/stock-check.yml` の平日朝8:00の定期実行（`cron: "0 23 * * 0-4"`）のときだけAI判定を使い、それ以外（15:40の定期実行・通常の手動実行）は無料のキーワード判定になるよう設定済みです。ダッシュボードの「ニュース」列で、AI判定が使われた銘柄には青い「AI」の小さいラベルが付きます。
- **有効化の手順**:
  1. [console.anthropic.com](https://console.anthropic.com/) でAPI用アカウントを作成し、支払い方法を登録してクレジットをチャージする（普段お使いのClaude.aiの契約とは別のアカウント・別料金体系です）
  2. 発行されたAPIキーを、リポジトリの「Settings」→「Secrets and variables」→「Actions」→「New repository secret」で `ANTHROPIC_API_KEY` という名前で登録する
  3. これだけで、次回の平日朝の自動実行からAI判定が使われるようになります（設定不要・自動で切り替わります）
- **手動実行でAI判定を試したい場合**: 「Actions」タブ→「日本株テクニカルシグナルチェック」→「Run workflow」を開くと、「ニュース判定にAI(Claude API)を使う」というチェックボックスが表示されるので、チェックを入れて実行すると手動実行でもAI判定を試せます
- `ANTHROPIC_API_KEY` を登録しなければ、平日朝の実行でも自動的に無料のキーワード判定にフォールバックするので、何も設定しなければ今まで通り完全無料のままです
- 頻度を変えたい場合（例: 平日朝夕2回ともAI判定にする、など）は、`.github/workflows/stock-check.yml` の `USE_AI_NEWS` の行にある条件式を編集してください

## シグナル判定ロジックについて

以下の3系統を組み合わせています。複数が同時に成立するほど「強いシグナル」（スコア=一致した根拠の数）として扱われます。

- **移動平均クロス**: 5日線が25日線を上抜け（ゴールデンクロス＝買い）／下抜け（デッドクロス＝売り）
- **RSI(14)**: 30を上抜けたら売られすぎからの反発（買い）、70を下抜けたら買われすぎからの反落（売り）。RSIが70以上/30以下の水準自体も過熱警戒として計上
- **MACD**: MACD線がシグナル線を上抜け（買い）／下抜け（売り）

これに加えて、精度向上のため次の2つの参考情報を付加しています(スコアの計算式自体は上記が基本ですが、出来高確認はスコアに加点されます)。

- **出来高確認(スコアに加点)**: ゴールデンクロス/デッドクロスが発生した日に、出来高が直近20日平均の1.5倍以上あれば「出来高急増を伴う」根拠を追加してスコアを1つ加点します。出来高を伴わないクロスより、出来高を伴うクロスの方が一般に信頼度が高いとされるためです。
- **長期トレンド注意(スコアには影響しない別枠の表示)**: 長期線(SMA75)に対して逆行する方向のシグナル(下降トレンド中のBUY、上昇トレンド中のSELL)が出た場合、ダッシュボードに「⚠」の注意書きを表示します。「見せかけの反発／一時的な調整」の可能性がある、という参考情報です。スコア自体は変わりませんが、後述のLINE通知の要否判定には使われます。

ロジックは `signals.py` にまとまっているので、条件の追加・調整も可能です。

## LINE通知の条件について

以前はBUY/SELLが出た銘柄をすべて通知していましたが、根拠が1つだけの弱いシグナルまで通知するとノイズが多くなるため、現在は次の条件で通知の要否を絞り込んでいます（ダッシュボードにはこの条件に関わらずすべてのシグナルが表示され続けます）。

- 通常: スコア(根拠の数)が **2以上** の場合のみLINE通知
- 長期トレンドへの注意（⚠）が出ている場合: より慎重を期して、スコアが **3以上** そろって初めてLINE通知

閾値を変更したい場合は `analyze.py` の `MIN_SCORE_TO_NOTIFY` / `MIN_SCORE_TO_NOTIFY_AGAINST_TREND` を編集してください。

## 実行時間の効率化について

ウォッチリスト・保有銘柄の株価取得は、以前は銘柄ごとに個別リクエスト＋1秒待機を繰り返していましたが、現在は買い時ランキングと同じように複数銘柄をまとめて1回のリクエストで取得する方式に変更し、実行時間を短縮しています。また、同じ銘柄がウォッチリスト・保有銘柄・買い時ランキングの複数箇所に重複して登場する場合、ニュース取得・AI判定は銘柄ごとに1回だけ行い、結果を使い回すことでリクエスト数とAI利用料の無駄を減らしています。

## 注意事項

- yfinance は無料の非公式データソースのため、まれに一時的な取得エラーが起きることがあります（`analyze.py` は1銘柄が失敗しても他銘柄の処理を継続します）
- 実際の自動発注（売買の自動執行）は行いません。あくまでシグナルの通知とダッシュボード表示のみです
- 本システムの利用によって生じたいかなる損失についても責任を負いかねます
